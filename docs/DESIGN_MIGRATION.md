# نقل تجربة Arabic-1s إلى مِرسم

## المرجع والنطاق المصحح

- المرجع: `techtouchAI/Arabic-1s` عند `3f91b0bf2ac2871acdfc0036721cc836162ba0e1`.
- خط أساس مِرسم: `067fdf119cc8b8bcc73adc250ff3f9c76a5d110c`.
- النطاق **ليس تغيير Theme فقط**. يشمل تجربة إعداد الأسئلة وبنكها وحفظ الأوراق والمعاينة والاختبار والبحث وملف المدرس، مع إبقاء مادة التربية الفنية وترتيبها.
- التقرير السابق الذي استثنى الحفظ التلقائي ووظائف الامتحان لم يعد يصف المطلوب أو التنفيذ.
- لا تُنقل قواعد العربية أو الإملاء أو توزيع درجاتها إلى الفن: تُربط أدوات المرجع بنماذج الفن الحالية: صح/خطأ ← اختيار متعدد ← أسئلة مفتوحة، ثم العملي.

## السبب الجذري وطريقة المعالجة

كان النقل الأول مقتصرًا على الألوان والمكونات والتنقل؛ لذلك ظلت شاشات الأسئلة ومسارات العمل مختلفة وظيفيًا. التشابه في المظهر لا يعوض غياب الاختيار الجماعي والتحرير والحفظ والمعاينة. عولج ذلك بتوسيع طبقات المجال والتخزين والعرض معًا، دون استبدال مستودع المنهج أو إعادة ترتيب بياناته.

تدفق البيانات: محتوى الفن المقروء فقط ← `ExamComposerState` (اختيار وتعديلات خاصة بالمسودة) ← لقطة مسودة كاملة في `SavedExamLibrary` ← `SavedExamStore`/SharedPreferences. تتشارك المعاينة وتصدير Word نموذج `ExamPaper` وصياغة الأسئلة. تظل إعدادات القراءة منفصلة عن تنسيق الورقة، ويظل أفضل تقييم للوحدة منفصلًا عن سجل جولات الاختبار التفاعلي.

## قرارات التوافق والاعتماديات

- تبقى هوية مِرسم وصفوف الفن الثلاثة وصوره ولوحاته ومحتواه محفوظة؛ لا نسخ لمادة اللغة العربية.
- لا تغيير لشيفرة بناء DOCX أو لترتيب الأسئلة في ملفاته. أضيفت أدوات حول نموذج الورقة الحالي بدل بناء نموذج موازٍ خاص بمرجع العربية.
- أضيف `file_selector: 1.1.0` لإتاحة حوار Save As الأصلي مثل المرجع؛ بقية الحفظ يستخدم SharedPreferences الموجود أصلًا. لا Isar أو ملفات `.g.dart` في هذا المشروع. مولدات تسجيل الإضافات الأصلية تُدار بواسطة Flutter أثناء البناء.
- حفظ الصور عبر MediaStore يستخدم مساحة الصور العامة مع IS_PENDING والتنظيف عند إخفاق الكتابة. لا أذونات جديدة في Manifest.

## نتائج التحقق وحدوده

النتائج المحلية المنفذة:

- `python3 tools/verify_content.py`: **1404 تحققات ناجحة**؛ 11 وحدة، 37 موضوعًا، 73 سؤالًا، 10 لوحات، 14 رسمًا.
- `python3 tools/verify_design_content.py`: **49 ملفًا مطابقًا** لخط الأساس.
- `python3 tools/test_verify_design_content.py`: **5 اختبارات ناجحة** لحماية النص والترتيب وإضافة/حذف الملفات.
- تنسيق وتحليل صياغة Dart باستخدام `@wasm-fmt/dart_fmt` خارج المستودع؛ هذا ليس تحليل أنواع ولا بديلًا عن Flutter.
- تدقيق `git diff --check` قبل الرفع.

Flutter/Dart غير مثبتين محليًا، ومضيف تنزيل SDK خارج قائمة الاتصال المسموح بها. لذلك لا تُنسب أي نتائج Flutter أو Android أو Windows إلى هذه البيئة. يتم تنفيذ التحليل ومجموعة الاختبارات وبناء المنصتين في GitHub Actions؛ المرجع النهائي هو آخر SHA لا نجاح النسخة الشكلية القديمة.

أظهرت دورات CI أخطاء عقود فعلية (اسم دالة تسمية النوع، وتمرير أعداد بدل نصوص إلى محول الأرقام، واستيراد زائد). صُححت أسبابها بدل إسكات التحليل. تُسجل نتائج التشغيل الأحدث في تقرير التسليم ووصف PR #11 بعد اكتماله؛ التشغيل الفاشل أو الجاري ليس نجاحًا.

اختبارات التخطيط والبناء لا تثبت المطابقة البصرية على مستوى البكسل ولا نجاح حوار النظام على جهاز حقيقي. يبقى فحص Android/Windows اليدوي، ومعاينة مطبوعات طويلة وخطوط Word المثبتة، شرطًا للاعتماد البصري النهائي.
